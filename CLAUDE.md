# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Langue

Toujours répondre à l'utilisateur **en français** (les explications, résumés et messages). Le code, les noms de symboles et les commentaires existants restent dans leur langue d'origine.

## What this is

superkitty is a **terminal emulator for macOS dedicated to using Claude Code**. It's "a real terminal like kitty" (full PTY, runs any shell program) but built to fix specific frictions the author hit using Claude in kitty:

1. No drag & drop of images.
2. Closing the terminal kills sessions — they don't resume.
3. Everything is raw shell, no clean UI.
4. (kept, liked) the window/pane system.

The project is built friction-first: each milestone removes one pain point. macOS-only for now.

## Commands

All run from the repo root.

- `npm install` — install frontend deps (run once, and after pulling).
- `npm run tauri dev` — **the main dev command**: launches Vite + the native window with hot reload.
- `npm run dev` — frontend only in a browser (no PTY/native APIs; rarely useful here).
- `npm run build` — type-check (`tsc`) + production frontend build.
- `npm run tauri build` — produce a distributable macOS app bundle.

Rust backend (in `src-tauri/`, needs `source "$HOME/.cargo/env"` if cargo isn't on PATH):

- `cargo check` — fast compile check of the Rust backend.
- `cargo build` — full build.

There is no test suite yet.

## Architecture

Tauri 2 app: a **Rust backend** (`src-tauri/`) and a **React + TypeScript + Vite frontend** (`src/`) that talk over Tauri's command/event bridge.

### PTY + persistence (the core trick)

`src-tauri/src/pty.rs` owns all terminal sessions. Each UI terminal is backed by a real PTY (via the `portable-pty` crate) and is one of **two kinds** (`PaneKind`, decided per pane and passed to `pty_spawn` as `kind`):

- **`raw` — the default (⌘D).** A normal, *ephemeral* terminal: the PTY runs `$SHELL -l` **directly** (no tmux), optionally under `sandbox-exec` (idea #5). `$SUPERKITTY=1`/`TERM` go straight via `cmd.env` (the child *is* the shell, not a fork of the shared tmux server — so no env-leak concern). Closing the pane SIGHUPs the shell (`raw_hangup`) — the terminal is gone, nothing accumulates. Scroll is xterm-native (its own `scrollback`); cwd/foreground come from **libproc** (`tcgetpgrp` → the foreground pgid → `proc_pidinfo`/`proc_pidpath`), the non-tmux equivalents of `#{pane_current_path}`/`#{pane_current_command}`.
- **`tmux` — opened on demand** (palette / right-click / `⌥⌘D`, "Nouvelle fenêtre tmux"). The original persistence trick: the PTY runs **`tmux new-session -A -D -s superkitty-<id>`** (attach-or-create, detach-others). A *newly created* session runs a fresh login shell (idea #7) optionally sandbox-wrapped; tmux ignores that trailing command on an `-A` reattach, so reopening resumes the prior live state — the create-vs-reattach split. Only tmux panes survive a window close and appear in the `⌘B` session sidebar.

This is what makes **tmux** panes survive a window close: their real processes (including a running `claude`) live inside the **tmux server**, not the PTY. Closing the window only drops the PTY (tmux detaches); reopening with the same `id` re-attaches and restores scrollback + the live session. `pty_detach` removes our handle **without** killing tmux — the normal close path for a tmux pane. A **raw** pane has nothing server-side, so its `pty_detach`/`pty_kill`/unmount all just SIGHUP the shell.

**Why two kinds (the pivot, 2026-06):** every pane used to be a tmux session, which *leaked* — `pty_detach` keeps tmux alive and nothing GC'd them, so dozens of dead sessions piled up (observed: 59 live, 2 attached). Raw-by-default fixes it at the source (close = gone); tmux is now a deliberate opt-in for the sessions you actually want to resume. The remaining gap (a GC/"Nettoyer les sessions" command for *deliberate* tmux panes) is the not-yet-built Phase D — see `IDEAS.md` and the `session-architecture-pivot` memory.

Backend commands (registered in `src-tauri/src/lib.rs`): `pty_spawn` (takes optional `cwd`, `session`, `sandbox`, plus an `on_output` Tauri `Channel`), `pty_write`, `pty_resize`, `pty_detach`, `pty_kill`, `pty_cwd`, `pty_foreground`, `pty_scroll_state` / `pty_scroll_to` / `pty_scroll` (custom scrollbar + kitty scroll keys via tmux copy-mode), `tmux_list_sessions` / `tmux_kill_session` (session sidebar, idea #2), `play_sound` (`afplay` cue on agent-done, idea #6), `install_claude_hooks` / `uninstall_claude_hooks` (default-on *semantic* agent-done hooks, idea #6 — see below) + `clear_stale_signals` (wipe leftover signal markers at launch), `save_image` (write a pasted clipboard image to `~/.superkitty/dropped/`, idea #4), `list_files` (git-aware file list for the `⌘P` picker, idea #15), `list_dirs` / `shell_history` / `pane_context` (the Warp-style command launcher + status bar, idea #24: directory completion for `cd`, recent `$HISTFILE`/`~/.zsh_history` commands de-duplicated, and a per-pane `{ node, branch, files, insertions, deletions }` blob from `node --version` + `git` run in the pane's cwd). macOS notifications go through **`tauri-plugin-notification`** (sent from JS in `App.tsx`'s `handleBell`, attributed to superkitty's own bundle — far more reliable than the old `osascript`/"Script Editor" path). A per-session reader thread streams raw output bytes through the per-mount `on_output` **`Channel`** passed to `pty_spawn` (a binary IPC body — chunks ≥1 KiB ride Tauri's fetch path as octet-stream, avoiding the ~4× JSON number-array expansion that froze the UI under heavy concurrent output); it still fires `pty://exit/<id>` when the PTY ends and emits `pty://bell/<id>` on a BEL byte — now with a `BellPayload { kind }` (`stop` | `notification` | `unknown`) so the frontend can tell a real turn-end from an ambiguous bell (agent-done detection, idea #6) — as ordinary events (rare + tiny).

**Agent-done reliability + *semantics* (idea #6).** A bare BEL (`0x07`) carries no meaning and also rings mid-work (a sub-agent finishing, etc.), which produced **false "agent terminé" notifications**. The fix makes the signal *semantic*: an OS notification fires **only** on a real turn-end or when Claude is blocked on you, never on an ambiguous bell. The chain: (1) `pty_spawn` still forces the tmux options that forward a raw BEL to our master PTY — `visual-bell off` + `bell-action any` + `monitor-bell on` (a default `bell-action other` forwards *nothing* for a single-window always-current session → the classic silent failure); (2) the **BEL is now just a doorbell**, the *kind* rides a per-pane **marker file**: `install_claude_hooks` writes **default-on** (Settings → Notifications → "Notifications fiables") per-event `Stop`/`Notification` hooks into `~/.claude/settings.json`, each gated on `$SUPERKITTY`, that **touch an empty marker then ring the BEL** — `[ -n "$SUPERKITTY" ] && { : > "$HOME/.superkitty/signals/$SUPERKITTY_PANE.{stop,notif}"; printf '\a' > /dev/tty; } ; true # superkitty-bell` (the `; true` forces exit 0 so it's a silent no-op in plain kitty/iTerm). **`SubagentStop` is deliberately NOT installed**, so a sub-agent finishing never signals. The reader thread, on a real BEL, consumes the pane's `.notif` (wins) or `.stop` marker and emits `BellPayload { kind }` (`notification` | `stop` | `unknown` when no marker); `handleBell` (`App.tsx`) maps `stop` → green "terminé" cue, `notification` → orange "te réclame" cue (`need` set), and **`unknown` → badge-only, never a notification/sound** (the actual bug fix). OS cues keep their ~500 ms per-pane debounce. Markers are empty files (no `cwd`/`session_id` on disk) in a 0700 `~/.superkitty/signals/` pre-created per pane; stale ones are wiped at launch (`clear_stale_signals`) and per spawn. `SUPERKITTY_PANE=<id>` identifies the pane to the hook — exported via `cmd.env` for a **raw** pane (the child IS the shell) and **baked into the pane shell command string** for a **tmux** pane (NOT `cmd.env`: tmux forks panes from the *server* daemon, so a client-side env var would leak/not-reach — same rule as `$SUPERKITTY`). The hook merge is append-only and idempotent (a `# superkitty-bell` sentinel) and **replaces any prior superkitty group** so upgrades take; `uninstall_claude_hooks` strips it back out. Default-on is reconciled at launch (App effect: install if the setting is on, idempotent; a one-time migration flips the legacy opt-out OFF→ON unless the user set it explicitly, tracked via `reinforceAgentDoneUserSet`). A global Quake hotkey `⌃\`` (`tauri-plugin-global-shortcut`, registered in `lib.rs`) shows/hides the window and emits `quake://shown` (idea #19; needs macOS Accessibility permission to capture system-wide).

`PtyManager` (a `Mutex<HashMap<id, PtyInstance>>`) is Tauri-managed state. The `id` is the stable identity of a session — reusing an id reconnects to the same tmux session, so ids must be chosen deliberately, not randomly per mount. Each `PtyInstance` stores its **`session_name`** (usually `superkitty-<id>`, but an *adopted* external/raw tmux session when the sidebar attaches one), its **`kind`** (raw|tmux) and the **`child_pid`** (the raw shell's pid, captured before the reader thread takes ownership — used for libproc cwd/foreground and the close-time SIGHUP). `pty_spawn` takes an optional `session` name; the lifecycle commands (`pty_kill`/`pty_detach`/`pty_cwd`/`pty_foreground`/`pty_scroll*`/`pty_redraw`) **branch on `kind`**: a raw pane uses the libproc/SIGHUP/xterm paths, a tmux pane uses the stored session name.

### Session sidebar (idea #2)

`src/SessionSidebar.tsx` is a `⌘B`-toggled panel listing every tmux session from `tmux_list_sessions` (superkitty-prefixed first, then externals), with an attached/detached dot. Clicking a session **attaches** it via `App.openSession`: a `superkitty-<id>` session reattaches by reusing its pane id (`p<id>`, persists naturally); a raw/external session gets a fresh pane id mapped to its name in `AppState.sessions` (a `Record<paneId, tmuxName>` persisted to localStorage and passed to `TerminalView`'s `session` prop). The 🗑 button calls `tmux_kill_session` and drops the pane if it was open. `AppState.sessions` only holds *non-default* mappings; panes without an entry use `superkitty-<id>`.

### Display mode v2 — « Platinum Noir » project rail (idea #2, v2)

A second UI direction, toggled live: **`settings.uiMode` (`"classic" | "v2"`, persisted in `superkitty.settings.v1`, default `classic`)**. v2 is **a different chrome over the SAME engine** — a project = a `Tab`, a session = a pane; nothing is re-created. Toggle via the **`✦ v2`** pill in the v1 titlebar, the **`Vue classique`** button in the v2 topbar, the `⌘K` palette (`toggle-ui`), or **Settings → Apparence**. `src/ProjectRail.tsx` exports `ProjectRail` (left rail: projects = tabs, sessions = panes, harmonized status dots, agent-preset buttons on hover, legend, foot) and `V2Crumb` (breadcrumb `projet › fenêtre` + « ← grille du projet » when zoomed). The rail has **two widths**, persisted in **`settings.railMode` (`"full" | "mini"`, default `full`)** and toggled by **`⌘B`** (full ↔ mini; the `sidebar` palette command does the same in v2): **full** is the 280px panel, **mini** is a slim ~60px strip (`ProjectRail collapsed` branch — project tint-dots that select a tab with a `⌘1-9` tooltip; the active project's sessions rendered **« façon Warp »** as **agent-logo tiles** (`AgentIcon` from `s.agent`) with a **corner status badge** (`.mini-st-badge` — orange pulse = busy, hidden = idle) instead of the old tiny braille glyphs; an activity badge on non-active projects). There is **no `hidden`** anymore — the rail always stays as a navigation anchor (an old persisted `hidden` migrates to `mini`). The rail's own ‹ collapses full→mini, › expands mini→full. `ProjectRail` is rendered unconditionally in v2 at the **fixed first slot of `.body`** (before `.main-col`), so toggling width never shifts `.main-col`'s reconciliation index (no pane remount — same invariant as the v1↔v2 toggle). **Which agent a session runs** (for the mini tile's brand mark) is tracked in `paneAgent: Record<paneId, "claude"|"codex"|"gemini"|"generic">` state, set at launch in `newWindowInProject` by matching the spawned command's leading token to an `agentPresets` entry (`agentIconForCommand`). It is **reconstructed at startup** from the persisted `AppState.paneCommand` (`seedPaneAgents`) — honest again because a restored agent pane now actually **re-launches its agent** (it's no longer a bare shell). See "Re-launching a raw agent pane on restart" below. The v2 topbar (built inline in `App.tsx`) hosts the rainbow wordmark, the reused `LayoutPicker` (▦), ⚙ and the toggle. The **drill = the existing `zoomed` flag** (`drillPane` focuses a pane + zooms it; `backToGrid` un-zooms); `Esc` also un-zooms **but only when the terminal isn't focused** (so a zoomed pane's `claude`/`vim` still receives Esc — the project's #1 rule). Status (`paneStatus`) now has a **real orange « te réclame » (`need`)**: driven by the `Notification` hook (idea #6) — the awaiting-input signal that *used* to be undetectable (so orange was reserved/never lit) is now a true signal. Precedence: `need` (orange, the `need` set, clears on engage) → "busy" (live PTY output, `outputBusy`) → idle. The green "done" glow stays the bell/`activity` set (`.has-activity`/`finished` badge), still set on any kind of bell but distinct from the rail's orange. In v2 the terminal also switches to `PLATINUM_NOIR_THEME` (warm graphite, applied live, no remount); v1 keeps the user's xterm theme.

**Agent presets (the rail's logos).** Each project header carries, on hover, the configurable `settings.agentPresets` (`DEFAULT_AGENT_PRESETS` in `themes.ts`: Claude / Codex / Gemini). Clicking one calls `newWindowInProject(tabId, command)` → a fresh **raw** pane whose `initialCommand` (e.g. `claude`) is **baked into `pty_spawn`**, NOT typed in afterwards: the raw shell runs `$SHELL -l -i -c "<cmd>; exec $SHELL -l"` (tmux: `exec $SHELL -lic …`), so the agent appears immediately — never a prompt with the command being typed — and `exec $SHELL -l` drops you into a usable login shell when the agent exits. `-i` sources `.zshrc` so PATH/aliases resolve the agent exactly as in a normal interactive shell. The icons (`AgentIcon` in `ProjectRail.tsx`) are the **real brand marks** (simple-icons paths, CC0) rendered in white. `initialCommand` is a fresh-pane-only spawn input (`spawnCmdRef`), ignored on the HMR-rewire early-return.

**Re-launching a raw agent pane on restart.** A raw pane is ephemeral, so without help a restart would drop an agent pane back to a bare shell. Two persisted maps in the layout blob fix it: **`AppState.paneCommand`** (`Record<paneId, string>` — the **verbatim** launch command, e.g. `claude`) and **`AppState.paneCwd`** (its launch cwd), both written in `newWindowInProject` and pruned to live panes in `loadState`. At mount, `spawnCmdRef`/`spawnCwdRef`/`paneAgent` are **seeded** from them (`seedSpawnCommands`/`seedPaneAgents`, using `initialSettings.agentPresets` loaded once up front), so a restored agent pane respawns with its `initialCommand` → `pty_spawn` re-runs the agent. On **replay only** (never at first launch), the command is passed through `resumeCommand`: a Claude command becomes **`claude --continue`** (`RESUME_FLAG`, extensible per agent) to resume the folder's last conversation — the `--continue` form is derived at seed time, never stored. The launch cwd equals the cwd at quit (claude is a child process; it never `chdir`s the parent shell), so capturing it at launch is exact and is also what lets `--continue` find the right conversation. Limit (intrinsic to raw): the raw scrollback isn't byte-preserved — `--continue` redraws the conversation; byte-for-byte restoration needs a **tmux** pane. No backend change: `pty_spawn` already runs `initial_command` for raw panes, and its HMR early-return means a Vite reload never re-fires the command (only a fresh backend does). Plain ⌘D shells have no `paneCommand` entry → restore as fresh shells, unchanged.

**The non-negotiable invariant: toggling the mode must NOT remount any `TerminalView`** (an unmount fires `pty_kill`/`pty_detach` and loses a running `claude`). This holds because the panes' ancestor chain **`.app > .body > .main-col > .workspace` keeps a stable React reconciliation index in both modes**: every mode-dependent piece (topbar/titlebar ternary, `ProjectRail`, `V2Crumb`, `SessionSidebar`, `StatusBar`) is an `&&`/ternary at a **fixed sibling slot** — `.main-col` is *always* present (a transparent flex pass-through in v1, the crumb+grid column in v2), so it never changes position. **Never wrap `.main-col`/`.workspace` in a v2-only branch**, and never add `uiMode`/`theme`/`kind` to `Terminal.tsx`'s id-keyed mount effect. All v2 styling is scoped under **`.app.ui-v2`** in `App.css` (token overrides + rail/topbar/crumb + warm overlay interactive states), so **v1 is behaviorally unchanged**. Deferred (visual-only or future): the Worktrees node (idea #5), per-session timestamps, pins. See `handoff/2026-06-27-mode-affichage-v2-rail-projet.md`.

### Frontend terminal

`src/Terminal.tsx` (`TerminalView`) renders one pane with **xterm.js** (`@xterm/xterm` + fit/web-links addons). On mount it creates a Tauri `Channel<ArrayBuffer>`, calls `pty_spawn` (passing it as `onOutput`), forwards `onData` → `pty_write` and `onResize` → `pty_resize`, and on unmount calls `pty_detach` (never kills tmux). Output chunks arriving on the channel are **batched**: queued and flushed to `term.write()` at most once per animation frame, gated on the write callback (backpressure) — without this, a flood of output (several Claude sub-agents at once) calls `term.write()` synchronously per message and freezes the UI. Bytes stay binary end-to-end (`ArrayBuffer` → `Uint8Array`), so multi-byte UTF-8 is never split across reads. `active` pulls keyboard focus into xterm and shows the accent border.

### Tabs, panes & shortcuts

`src/App.tsx` owns the whole layout. State is `{ tabs, activeTabId }`; each tab is `{ panes: string[], focused, layout }` — a **flat, ordered list of panes** plus a named **kitty-style layout** (this replaced the old binary pane tree). All tabs stay mounted (inactive ones `display:none`) so switching tabs does NOT detach/reattach PTYs.

Layouts live in `src/layouts.ts`: a layout is a pure function `(n, focusedIndex, opts) → Rect[]` returning one fraction-rectangle (`{x,y,w,h}` in 0..1) per pane, ported from kitty (`kitty/layout/{grid,tall}.py`). Layouts: `tall` (default — one big main column left, rest stacked right), `fat`, `grid`, `horizontal`, `vertical`, `stack`. App renders each pane in an absolutely-positioned `.pane-slot` sized from its rect; `Terminal.tsx`'s `ResizeObserver` re-fits xterm automatically. **Every add/close recomputes all rectangles**, so the arrangement stays balanced and nothing piles up — that's the whole point vs. the old halving tree. `next_layout` (`⌃⇧L`) cycles layouts via `LAYOUT_CYCLE`.

`src/LayoutPicker.tsx` (idea #21) is the visual alternative to blind cycling: a ▦ button in the titlebar opens a popover drawing every layout as a thumbnail, scaled from the **active tab's real pane count** via the same `layoutRects()` (focused pane tinted accent; `stack` shown as offset cards). Clicking a thumbnail calls `App.setLayout` (persists like any layout change). It owns its open state and closes on Esc / outside-click.

Several self-contained overlay components are mounted by `App.tsx` and driven by its action functions:

Persisted to `localStorage["superkitty.settings.v1"]`. The **Raccourcis** pane edits the reassignable bindings (capture a new chord, remove/reset, conflict-steals), driven by `src/shortcuts.ts`.

- `src/CommandBar.tsx` (`⌘L`, idea #24) — **Warp-style command launcher**, a bottom-anchored overlay opened on demand (reassignable `command-bar` action + `⌘K` palette). Live fuzzy suggestions (reuses `fuzzyScore`): directories for `cd` (`list_dirs`), shell history (`shell_history`), file completion on the last argument (`list_files`). `↑/↓` navigate, `Tab`/`→` complete the selection into the input (drill `cd a` → `cd a/b`), `↵` **runs** it in the focused pane — `App.runInPane` does `pty_write` + `\r` (plain text, NOT bracketed paste, unlike `sendToPane`), `Esc` closes. Opening captures the pane's cwd + `pty_foreground`; if the foreground isn't a shell (claude/node/editor) it warns that the line will be typed into that program. Like the other toggles, its chord is handled before the "focus is in our own input" bail so `⌘L` also closes it.
- `src/PromptComposer.tsx` (`⌘E`, idea #16) and `src/Scratchpad.tsx` (`⌃⇧N`, idea #20) — multi-line text → focused pane (bracketed paste; `⌘↵`). Scratchpad is per-tab and persisted (`localStorage["superkitty.notes.v1"]`).
- `src/QuickPrompt.tsx` (idea #19) — the Quake dropdown shown on the `quake://shown` event: pick a project tab, type, `↵` sends + runs in that tab and re-hides the window.
- `src/StatusBar.tsx` (ideas #22/#24) — the thin bottom bar is **rendered in both UI modes** (the `!v2` gate was dropped; it stays a sibling after `.body`, so terminals never remount). **Bottom-left** it now shows a **Warp-style project-context group** (`sb-context`, idea #24): `⬡ node` · `📁 cwd` · `⎇ branch` · `📄 N • +ins −del`, each segment hidden when absent, fed by the `pane_context` poll in `App.tsx` (active tab's focused pane only, ~2.5s, cached by cwd) via the exported `PaneContext` type. Then the discrete **rotating shortcut tip** ("Astuce : `⌘D` pour…") that cycles ~every 9s (click advances). Tips come from `src/hints.ts` (`HINT_SPECS` curated list + `buildHints`), built from the **live** `resolveBindings(bindings)` + `formatChord`, so they reflect reassigned chords. `App` passes the array via `hints`; the bar's `×` flips `settings.hintsEnabled` off (also toggleable in Settings → Raccourcis, persisted in `superkitty.settings.v1`).

A single capture-phase `keydown` listener in `App.tsx` gates all of these: it **bails when focus is in one of our own text fields** (any `<input>/<textarea>` not inside `.xterm`) so typing never triggers shortcuts, while the terminal's own hidden textarea (inside `.xterm`) still gets them. Bell activity badges (idea #6) live in `activity: Set<paneId>`; per-pane sandbox flags in `localStorage["superkitty.sandbox.v1"]`; per-tab project name/tint (idea #17): each tab is assigned a **distinct colour** from the `TAB_COLORS` palette at creation (`pickTabColor` avoids reusing a sibling's), stored on `Tab.color` and persisted; **right-clicking a tab** opens `src/TabColorPicker.tsx` to recolour it (or "Auto" to clear it). `tabTint(t)` returns the stored colour, falling back to a cwd hash (`autoTint`) for legacy tabs without one; the result is applied to the tab dot and the focused pane border via the `--pane-accent` CSS var.

Pane ids (`p1`, `p2`, …) come from a monotonic counter and are the tmux session identity. The layout is persisted to **`localStorage["superkitty.layout.v1"]`** on every change and restored on launch (`loadState`), which reseeds the id counter past all restored ids — this is what makes a full app restart reattach to the same tmux sessions in the same arrangement. `normalizeTab` migrates any old binary-tree (`root`) entries by flattening their leaves into `panes`, so existing saved sessions still reattach.

Two close semantics: `pty_detach` (keep tmux alive) vs `pty_kill` (destroy it) — and **the kind decides which applies**. A **raw** pane is always killed on close (it's ephemeral) and never enters the `⌘⇧T` reopen history. A **tmux** pane: `closeFocused` (`⌃⇧W` / `⌘⇧D`) **detaches** it — its session stays alive — and pushes it onto the reopen history; `closeTab` (`⌘W`) kills the whole tab's sessions (with a confirmation when an agent is running, idea #13). The actual detach-vs-kill on unmount is driven by `Terminal.tsx` from its frozen `kind` prop (raw → `pty_kill`, tmux → `pty_detach`). Tmux closes feed the **`⌘⇧T` reopen history** (`AppState.closed`, persisted, capped): reopening a detached pane reattaches its live session, reopening a killed tab recreates each pane fresh in the same layout/cwd (idea #1) — each closed pane carries its `kind` so a reopened raw pane respawns a fresh shell and a tmux one a fresh session. `AppState.paneKind` (a `Record<paneId, "raw"|"tmux">` persisted in the layout blob) is the source of truth; a restored pane with no entry migrates to `tmux` (it predates the feature and has a live session). The layout blob also persists `AppState.paneCommand`/`paneCwd` (raw agent panes only) so a restart re-launches the agent — see "Re-launching a raw agent pane on restart" above.

Keyboard shortcuts are **reassignable** (idea #3): `src/shortcuts.ts` is the single source of truth — it defines every bindable action (`ACTIONS`: id, label, group, **default chords**), a layout-independent **canonical chord** derived from a `KeyboardEvent` (modifiers in fixed order + a key token: for the **alphanum/punctuation block** the token is the *produced character* `e.key` — mapped through a US shift-pair table `CHAR_CODE` so `,` → `Comma`, `]`/`}` → `BracketRight`, staying Shift-immune — so a binding follows the **printed** key on AZERTY/QWERTY alike; **digits** (`Digit/Numpad` excluded) **arrows, Enter/Tab, F-keys and dead/IME keys** keep the physical `e.code`; `chordFromEvent` returns `null` without a ⌃/⌥/⌘ so terminal keys pass through), `formatChord` for display, and the `superkitty.keys.v1` override persistence. AZERTY scope: `⌘1-9` work pressed **without** Shift (⌘ + the digit key → `e.code` `DigitN`); the bracket/backquote shortcuts (`⌃⇧]`/`⌃⇧[`/`` ⌃⇧` ``) are produced via Option on AZERTY (so `e.altKey` is set and they can't match) → use the `C+Tab`/`C+S+Tab` alternates or reassign. The single capture-phase `keydown` listener in `App.tsx` now **resolves the event's chord through a live lookup** (`lookupRef`, rebuilt when bindings change) to an action id, then runs the matching handler from a per-id `actions` map (the three overlay toggles — palette/settings/file-picker — are special-cased so the same combo also closes them). ### Gotchas

- **No React StrictMode** (`src/main.tsx`): its double-invoked effects would spawn/attach the PTY twice. Keep it off, or guard PTY spawns by id.
- `tmux` must be resolvable on the spawned process's PATH. In `npm run tauri dev` it inherits the launching shell's PATH (Homebrew tmux is fine). A Finder-launched bundle has a minimal PATH — if tmux isn't found in a built app, resolve its absolute path in `pty.rs`.
- Custom titlebar uses `titleBarStyle: "Overlay"` + `data-tauri-drag-region`; the CSS reserves left padding for the macOS traffic lights.
- The global Quake hotkey (`⌃\``) needs **macOS Accessibility permission** to capture keys system-wide; until granted (System Settings → Privacy & Security → Accessibility) it silently no-ops. Registration is best-effort in `lib.rs` so a failure never blocks launch.
- The sandbox (idea #5) is **write-confinement** (Seatbelt profile: reads open so node/git/claude work, writes limited to the project dir + temp + a few caches). Stricter read-confinement would likely break Claude's config/cache access, so it's intentionally not the default.
- **Keyboard focus can diverge from the "active" pane.** The accent border / `active` prop is React state; the real DOM focus on xterm's hidden textarea is set only by `onMouseDown={onFocus}` (click *inside* the pane) or `Terminal.tsx`'s `useEffect(…, [active])` (which fires only when the prop *changes*). So focus can leave xterm without the React state changing — on **window refocus** (Cmd-Tab / clicking the agent-done notification; WKWebView drops focus to `<body>`), on **overlay close** (the overlay input held focus), or on a **click on inert chrome** (titlebar/status bar). The pane then *looks* active but receives no keystrokes — the "arrow keys stop working in a claude menu" bug. Fix lives in `App.tsx`: a `focusActivePane()` helper (skips if one of our own inputs holds focus) wired to the existing `onFocusChanged` window handler, an `anyOverlayOpen` close effect, and a capture-phase `mousedown` on inert chrome — each via `requestAnimationFrame` so it runs after WebKit settles its own focus. (Raw panes only need this; a tmux pane has the *separate* copy-mode-after-scroll trap, cancelled on (re)attach in `pty.rs`.)

### Clipboard paste of files/folders (idea #4) — hard-won specifics

A ⌘V of a Finder copy was the source of a long debugging saga; the moving parts, so the next person doesn't re-derive them:

- **A real Finder ⌘C puts a *file-reference URL* on the pasteboard, not a path.** `clipboard_file_paths` (`pty.rs`) reads `public.file-url` off each `NSPasteboardItem` (`pasteboardItems()`), but that value is `file:///.file/id=6571367.1542935/` — an opaque node id. `NSURL.path()` only **half-resolves** it (→ `/Users`); you MUST go through **`NSURL.filePathURL()`** to get the true POSIX path. The legacy `NSFilenamesPboardType` is kept only as a *fallback* — modern Finder doesn't populate it; only `osascript 'set the clipboard to (POSIX file …)'` does (which is why the old standalone test "passed" while the app failed). Needs the `NSPasteboardItem` feature on `objc2-app-kit`.
- **The webview's DOM `clipboardData` is useless for the real path** (WebKit exposes only an icon preview / a `"Files"` type with empty `text/plain` + `text/uri-list`). The native NSPasteboard read is the only source of truth; the frontend just gates on "is there any file/image item?" then calls `clipboard_file_paths`.
- **`injectPaths` (`App.tsx`): image paths → bracketed paste (`ESC[200~ … ESC[201~`); everything else → PLAIN text; never shell-escape.** claude renders `[Image #N]` only for an *image* path sent as a bracketed paste (it then attaches the file). A bracketed paste of a **folder / non-image** makes claude try to attach it and **silently drop it** → nothing appears. So non-images go as plain text, which claude inserts as the literal path. And do **not** backslash-escape (`Analyse\ Savage\ Step`): claude wants the literal path; escaping breaks resolution and rendering for names with spaces.
- **The capture-phase `paste` listener must `stopImmediatePropagation()`, not just `preventDefault()`** — otherwise xterm.js's own paste handler ALSO reads the clipboard and double-injects (a single pasted image appeared twice).
- claude **only echoes pasted input when it's idle at the prompt** (and discards/garbles a rapid burst of ⌘V). When verifying, paste once into an *idle* pane.
- **Debugging tip:** `tmux capture-pane -p -t superkitty-<id>` shows what claude *actually* received/renders, independent of the (sometimes blank) xterm draw — the only reliable way to verify paste behavior without a screenshot.

### "Black / frozen pane" after a webview reload or remount

`pty_spawn` used to **early-return if a PTY for the `id` already existed**. On a Vite HMR page reload (or any remount) the Rust backend — and the old `PtyInstance` — stay alive (a page reload skips React cleanup, so `pty_detach` never runs), but the new xterm created a brand-new `Channel`. The early return left that channel **unwired**: the reader thread kept streaming to the dead old channel, the fresh pane got zero bytes, and no `pty_redraw`/`tmux refresh-client` could fix it (the bytes went to the dead channel). Fix: `PtyInstance.output` is a swappable `Arc<Mutex<Channel>>`; on remount `pty_spawn` **rewires** it to the new channel and returns, and the frontend's existing `pty_redraw` (`Terminal.tsx` `tryAttachRedraw` backoff) makes tmux re-send the screen → the pane repaints. A *clean* app restart never hit this (fresh backend → fresh spawn → `tryAttachRedraw`); only reloads/remounts did.

**The raw-pane variant (clean restart, v2 agent panes).** A *raw* agent pane (`claude --continue` re-launched on restart) could also come back **permanently black** — but for a different reason and through a different fix. `pty_redraw` was a **no-op for raw** (raw has no tmux client to `refresh-client`), and `tryAttachRedraw` was **skipped for raw** entirely, so a raw pane had *zero* repaint path: if claude's first paint was lost/partial (it drew before the `.pane-slot` had its final size, `fit()` ran on a 0px container at mount, or the rAF flush was throttled while the window was still settling), nothing ever repainted it — and even the "Cmd-Tab away-and-back" rescue (`App.tsx` `redrawAll` on `onFocusChanged`/`quake://shown`) did nothing, since it only called the no-op `pty_redraw`. Fix (three parts): (1) `pty_redraw` for a raw pane now **sends `SIGWINCH` to the foreground process group** (`raw_repaint` → `raw_fg_pid` → `killpg`, the non-tmux equivalent of `refresh-client`) — claude/Ink/vim redraw the whole screen on SIGWINCH even when the size is unchanged (no reflow; a bare shell prompt ignores it, harmless). (2) `Terminal.tsx` runs a bounded `scheduleRawRepaints` after a raw spawn (`[200, 700, 1600, 3200]ms`), each pass doing `fit()` + `term.refresh(0, rows-1)` + `pty_redraw` — claude needs 1-3s to draw its first frame, so a single immediate redraw lands too early; raw needs no retry-until since `raw_fg_pid` always exists. (3) `redrawAll` also calls `term.refresh()` per pane via `paneTerminals`, so the foreground rescue now un-blacks raw panes too. tmux keeps its original `refresh-client` path; raw uses SIGWINCH/xterm-refresh.

## Handoff briefs (handoff/)

When a bug or chantier is going to be handed off to another dev (human or a more senior agent) to investigate from scratch, write a **handoff brief** under `handoff/` instead of dumping the context into chat. A brief is an investigation dossier, not a ticket: it states what we *wanted*, what's *broken*, **what's already been tried with each attempt's verification status** (✅ verified / ❓ unverified / ❌ ruled out — this is what stops the next dev re-doing work), the relevant `file:line` references, and the remaining leads. See `handoff/README.md` for the naming convention (`AAAA-MM-JJ-sujet.md`) and the brief skeleton. **Workflow rule:** the dev who picks up a brief updates the *same* file as they go (attempts, statuses, what they eliminated); on resolution, set status `✅`, record the real cause + fix, and propagate anything durable into `IDEAS.md`/this file. Keep solved briefs as a trace.
