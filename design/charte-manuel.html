01 — Principe

Friction-first

Chaque jalon supprime une douleur précise rencontrée en utilisant Claude dans un terminal nu. On ne décore pas : on retire ce qui gêne.

« Un vrai terminal comme kitty, mais qui ne perd jamais une session Claude et n'oblige plus à vivre dans du shell brut. » Quatre frictions, supprimées une par une.

01 — Persistence

La session survit à la fermeture

Chaque pane est adossé à tmux. Fermer la fenêtre détache, ne tue jamais. Rouvrir réattache le run Claude vivant et tout le scrollback.

02 — Images

Drag & drop sans détour

On dépose une image dans un pane : son chemin est injecté en bracketed-paste. Claude affiche [Image #1] et travaille.

03 — UI

Une interface, pas du shell brut

Palette ⌘K, sélecteur de fichiers, compositeur, bloc-notes, notifications de fin d'agent. Tout reste sobre, rien n'est superflu.

04 — Fenêtres

Le système de panes conservé

Ce qu'on aimait dans kitty reste : onglets, panes, layouts auto-équilibrés. On garde le bon, on corrige le reste.

05 — Garde-fou

Sandbox par pane

Un pane peut confiner les écritures au dossier projet (profil Seatbelt). Les lectures restent ouvertes : node, git et claude continuent de fonctionner.

06 — Retour

Rouvrir, toujours

Un pane détaché ou un onglet fermé se rouvre avec ⌘⇧T : la session vivante revient, ou se recrée à l'identique. Neuf vies.

05 — Schémas

Vues techniques

Trois planches façon fiche d'atelier : la fenêtre éclatée et cotée, le flux PTY ↔ tmux, et la mécanique de persistence à la fermeture.

Fig. A — Vue éclatée Anatomie de la fenêtre · échelle libre

① titlebar overlay — réserve l'espace des feux macOS. ② sidebar ⌘B — liste les sessions tmux, point attaché / détaché. ③ pane actif — bordure accent, prend le focus clavier. ④ — chaque rectangle est un pane indépendant, recalculé à chaque ajout pour rester équilibré.

Fig. B — Flux PTY ↔ tmux Le cœur du dispositif · create-vs-reattach

Chaque pane lance tmux new-session -A -D : création au premier appel (shell de login frais), réattache ensuite. Les processus vivent dans le serveur tmux, pas dans le PTY — c'est tout le truc.

Fig. C — Cycle de vie La fenêtre se ferme, la session vit

La ligne accent ne s'interrompt jamais : tant que tmux tourne, la session reste. La fenêtre (encre) peut disparaître et revenir — au pire, ⌘⇧T la rappelle. C'est la garantie « neuf vies ».

07 — Tokens

Design tokens

Le système tient en quelques variables CSS. Une seule source de vérité : encres, accent, filets, échelle typographique, gouttière.

superkitty.tokens.css
:root {
  /* — encres & papier — */
  --paper:       #f4f1ea;
  --paper-2:     #ece7dc;
  --ink:         #1a1714;
  --ink-soft:    #4a443c;
  --ink-faint:   #8a8275;

  /* — accent unique — */
  --accent:      #d8552f;  /* orange brûlé */
  --accent-deep: #a83c1c;

  /* — filets & grille — */
  --hair:        #c8c0b0;
  --hair-strong: #b3a994;
  --grid-max:    1180px;
  --gut:         clamp(20px, 4vw, 56px);

  /* — typographie — */
  --font-sans:   'Space Grotesk', sans-serif;
  --font-mono:   'Space Mono', monospace;
  --ratio-4:     1.5rem;
  --ratio-6:     clamp(2.5rem, 7vw, 5.5rem);
  --ratio-7:     clamp(4rem, 16vw, 13rem);
}

À propos

superkitty est un émulateur de terminal macOS dédié à Claude Code : un vrai PTY adossé à tmux, pensé « friction-first ». Construit avec Tauri 2, React + TypeScript et xterm.js côté interface, Rust côté backend.
